# HealthController

**Package:** `com.bank.epricing.controller`
**File:** [`HealthController.java`](../../src/main/java/com/bank/epricing/controller/HealthController.java)
**Stereotype:** `@RestController`, `@RequestMapping`

---

## Purpose

`HealthController` provides **custom observability endpoints** that supplement Spring Boot Actuator's built-in health and metrics endpoints. It exposes business-level health information, live Micrometer metrics summaries, and demonstration endpoints for the observability stack.

---

## Endpoints

### GET `/health` — Application Health Summary

Returns a structured JSON health document including:
- Status and service identification
- Dynamically injected application version from `BuildProperties` (auto-generated by Maven `spring-boot:build-info`)
- Timestamp and database connectivity status with driver product and version details

**HTTP Method:** `GET`
**Response Status:** `200 OK`

**Example Response:**
```json
{
  "status": "UP",
  "service": "epricing-service",
  "version": "1.0.0-SNAPSHOT",
  "timestamp": "2026-09-07T10:15:00",
  "database": {
    "status": "UP",
    "product": "PostgreSQL",
    "version": "16.1"
  }
}
```

> **Dynamic Versioning:** Rather than hardcoding the version string, `HealthController` injects Spring Boot's `BuildProperties` bean. When `pom.xml` version updates, the `/health` endpoint updates automatically without manual edits.

This endpoint is intended for:
- Load balancer and Kubernetes liveness probes (`http://localhost:8080/api/v1/health`)
- Grafana "service health" panels that require immediate visibility into database connectivity and build version

## Observability Demo Endpoints (`MetricsDemoController`)

> **Note:** Demonstration endpoints are separated into [`MetricsDemoController.java`](../../src/main/java/com/bank/epricing/controller/MetricsDemoController.java) and annotated with `@Profile("!prod")`. They are active only in development and staging environments to prevent error metric poisoning in production.

### GET `/metrics-demo/simulate-slow` — Simulate Slow Request
Artificially introduces a processing delay to demonstrate slow operation detection in Grafana. Used by traffic generators to test latency panels.

### GET `/metrics-demo/simulate-error` — Simulate Error
Deliberately triggers an error path to verify Prometheus error alert firing (`pricing_requests_total{type="failed"}`). Disabled in production via `@Profile("!prod")`.

### GET `/metrics-demo/generate-load` — Generate Load
Executes a batch of internal pricing calculations to simulate sustained throughput in Grafana dashboards. Disabled in production via `@Profile("!prod")`.

## Actuator Integration

Spring Boot Actuator (running on port `8081`) provides the canonical health, metrics, and Prometheus endpoints. `HealthController` is NOT a replacement for Actuator — it is a **supplement** that exposes business-context health data that Actuator does not understand.

| Actuator Endpoint | Purpose |
|---|---|
| `GET :8081/actuator/health` | System-level health (DB, disk, ping) |
| `GET :8081/actuator/prometheus` | All Micrometer metrics in Prometheus format |
| `GET :8081/actuator/loggers` | View/change log levels at runtime |
| `GET :8081/actuator/env` | View configuration properties |
| `GET :8081/actuator/threaddump` | Current JVM thread state |
